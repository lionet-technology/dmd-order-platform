# DMD GĐ1 — Debt aging simplification and Admin action queue (23/10/2026)

## Owner decisions implemented
- The age clock for a finalized Statement begins at **period_end**, not at the day Finance clicked Finalize. 14/28-day limits display in Debt Management as elapsed/allowed weeks (e.g. `1/2 tuần`, `3/4 tuần`); other terms display elapsed/allowed days.
- Snapshot Finalize now atomically creates one **immutable** `statement_v2_aging_basis` row per Statement containing its incremental principal economic basis and final event checkpoint. An associated immutable total is also stored inside the finalized Statement JSON; the index must match the snapshot. No Payment-to-Statement FIFO allocation is introduced. Journal settlement, Debt-transfer and posted interest events are not counted as *new principal* obligations. Credit memo reduces new obligation for the period; negative net bucket is not by itself REVIEW, but uncovered principal still is.
- Current period economic activity affects purchasing power immediately. The age anchor does not arise from an unfinalized period. Projected **unposted** Debt interest is kept separately from principal age; UI differentiates posted unpaid vs unposted estimated interest. Explicit Payment/finalize continues to post interest.
- Snapshot read uses the immutable light index when available. **Historical finalized snapshots without that index remain read-compatible through their original movement projection**, preserving immutability and avoiding silent backfill.
- When there is unexplained historical obligation coverage, Admin sees an explicit one-time **Opening Aging** form with amount, date and evidence; backend verifies coverage deficit, exact cents, age reference not in the future and not later than first Statement, Admin RBAC, plus immutable row and financial audit. This supplies only an age reference, never Balance, Payment or Debt money. The form is not presented for non-legacy REVIEW causes such as altered historical source.
- New Admin action queue on Dashboard: submitted UPS/Chuyên tuyến Orders missing total customer price (priority if submission period has already ended); partial Carton labels without a current authorized override; Client debt-age REVIEW requiring verification. Each opens the Order or selected Client Debt, plus a Statement link. Dashboard requests are read-only, Admin-scoped.
- Statements still finalize in contiguous order, are immutable and refuse to finalize with eligible unpriced submitted Orders. Later activity can continue; late postings belong to their posting period, no prior Statement rewriting.

## Remaining nitpicks / boundaries
1. **P1 legacy age provenance:** old V2 snapshots use the original movement fallback until their coverage is approved. Admin opening **happy path is now tested on a constructed synthetic cutover fixture (17 checks)**, but actual imported historical documents/production DB provenance, backup and reconciliation still require separate supervised acceptance.
2. **P1 product definition:** Account-level principal aging is a *coverage model*, not a legal allocation of individual Payments to invoices. Validate real Credit Note, claim, cancelled-order and partial-payment cases against finance owners before pilot.
3. **P1 operational scale:** the Dashboard scans active Client financial projections for REVIEW; with thousands of Clients this could be slow even though Ledger rows now paginate on server. Cap/paginate or materialize a dedicated exception index when metrics justify.
4. **P2 old immutable Statement JSON:** old periods cannot be silently rewritten to backfill new aging rows. The compatibility fallback may still parse large JSON. A separately verified one-time index backfill requires backup/provenance approval.
5. **P2 manual date/term:** the existing Debt Account has a manually configurable deadline, while statement-derived overdue uses period_end+credit_term_days; the UI intentionally shows both. Align contractual interpretation before external billing letters.
6. **P2 interest:** unposted projection still loops completed days, preserving per-day rounding. For multi-year Debts, benchmark and then consider interval arithmetic without changing cents.
7. **P2 browser UAT:** actual Chrome clicks through new Admin Dashboard, opening action and several roles/mobile are **not yet verified in this patch**. Domain/API regressions are not a substitute for that.

No unknown DB was reset; no live carrier label, bank transfer or production deployment was performed. `Codex/` must remain untouched.
