# Temporary UPS / Chuyên tuyến manual sale price — verification 20/10/2026

## Owner request and scope
- UPS and Chuyên tuyến may create Client Orders **without an automatic price table**. Client selects an allowed Route, imports a file or enters manual one/multiple Cartons, saves Draft, explicitly submits the Order. API support for a new dedicated public nested-Carton schema is **deferred**; Client UI and existing Client Orders JSON API share the current normalized internal `carton_rows` payload.
- Admin enters the **total customer selling price of the entire Order** (USD), **not supplier Net Cost**, once when first issuing Tracking/Label. Do not multiply it by Carton count; Client does not input its own selling price. The Route's max-Carton limit and Client's actual purchasing room remain authoritative.
- ePacket/Yun remain one Carton and retain **automatic priced** handling, unchanged.

## Implementation
- `src/lib/manual-route-price.ts`: strict eligible services UPS / Chuyên tuyến only; requires the Client to have submitted the purchase request and blocks Orders in HOLD, case/warehouse Hold or held Routes before reserving any money; active Route and Carton policy check; mandatory positive exact-cent USD price; refuses re-pricing after Tracking, Price Snapshot or Reserve. Writes one manual price snapshot, Order Sales Price and Total Due with an audited event and *one* Reserve, atomically. Credit gate remains active; neither an unpriced Draft nor pending Order reserves a fake zero amount.
- `route-pricing.ts`: Client can submit unpriced UPS/Chuyên tuyến into Admin pending queue; **no Charge/Reserve** at this step. Explicit retry does not duplicate service-purchase events. A common `assertConfiguredPurchase` guard blocks any Tracking insert via any operational path until Admin price has been recorded.
- `/api/orders/tracking-queue`: editable per-Order **Giá bán thủ công (USD/Order)**, including spreadsheet Excel import/export, in the same transaction as multiple Carton Tracking/Label insertion. Manual-entry Order is visible in Admin queue even without Supplier Purchase Template; file export still requires an approved Template and never silently falls back to generic.
- `/api/orders/[id]/trackings` and Admin Order detail panel: same price gate for individual Order Tracking/Label, including partial or complete updates. Admin cannot edit price after it locks.
- First actual Label triggers existing `completeReserve`: Customer Order Charge exactly once, releases Reserve, captures immutable financial event for Statement V2. More Carton Labels and retries **do not repeat Charge**. Invalid/missing/manual price over purchasing room causes transaction rollback (no price/Reserve/Tracking/Charge partial persistence).
- Client manual UI has **Single Carton / Multiple Cartons** selector only for Routes whose `max_cartons_per_order>1`. Follow-up safeguards: derive/lock `Carton Quantity` once the user builds multiple Cartons, and keep file-import rows read-only so editing does not desynchronize the grouped Order from its underlying Carton records. Multiple shows Carton 1 in existing sheet and editable additional Carton fields; Client still supplies only one recipient/address and Client Order ID. Preview has a dedicated **Chờ Admin nhập giá** state instead of calling `.toFixed()` on unavailable manual price/dimensions or showing a misleading zero-priced purchase total. Submitted unpriced Order is immutable to Client edits pending Admin processing.
- Old synthetic Purchase Engine fixture that assumed two-carton ePacket has been aligned to UPS with an explicit manually priced Route, as approved.
