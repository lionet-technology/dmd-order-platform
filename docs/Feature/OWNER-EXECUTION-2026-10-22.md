## Current behavior (supersedes conflicting historical notes)
- Balance Ledger has five horizontal task tabs: Client/Ledger, Debt Management, Payment Reconciliation, Refund Balance, Statement. Each mounts its existing workspace; no duplicated money commands. Admin/Sales/Client retain their scopes. BOD/Finance keep their separate permitted finance workspaces.
- Debt tab shows one existing account, remaining principal, posted unpaid interest, amount due, Debt deadline/status, credit term and independently derived oldest covered finalized Statement/date/due/status. Admin can convert negative Balance with reason/proof text, explicit before/after review, actor-scoped idempotency receipt and atomic immutable transfer/audit. Existing rate/extension commands are surfaced; history includes principal changes, posted interest and Payments (latest 100 entries per category).
- Manual UPS/dedicated orders may be submitted without price and receive Tracking/Label first. Missing price is explicitly flagged. Finalization rejects submitted unpriced orders whose submission is on/before the period end, including unresolved earlier periods; invalid/empty legacy snapshots, nonpositive prices and unparseable submission dates also fail closed. Cancellation excludes the order from this gate.
- Later manual price writes one Reserve and, if an active Label already exists, one Charge in the same serialized command. Same-price retries are accepted; different confirmed prices are rejected for separate adjustment. The current submitted order is allowed to exceed current purchasing headroom; subsequent purchasing uses normal negative Balance/credit/maturity policy. No automatic new Debt account.
- Partial carton labels remain INCOMPLETE unless Admin explicitly confirms primary tracking/multipage PDF with a reason. Audit stores the exact active tracking/carton/label fingerprint. A changed fingerprint invalidates the override; no fictitious carton tracking is created. Detail command can reuse an unchanged prior override. Manifest readiness recognizes the valid override; carton-level scanning still needs real carton data.
- The pricing DB guard retains its Admin role check and Tracking/Charge/fulfillment exclusions. Its narrow amendment context exists only inside the transaction and is removed before commit; failures roll it back. Both guard replacement at startup and role-schema rebuild preserve/recreate it atomically. Direct pricing edits outside the context remain forbidden.
- Generic order and shipment editing are locked once Tracking exists. Unpriced manual orders can be edited by Admin before Tracking. Admin can amend an already priced, untracked, uncharged Order through the existing Order save: quote/Reserve are replaced in one transaction and the original quote/Reserve are captured in audit. Invalid amendments roll back both. Client cannot be changed. After Tracking or Charge this flow is denied. The dedicated carton-structure API uses the same Admin amendment transaction before Tracking, updates carton measurements, and preserves/requotes the customer total according to manual/automatic route rules. After Tracking its sensitive fields stay locked.
- ePacket/Yun single-carton limits, default one Lot, deferred carrier multi-carton API and approved commercial-rate configuration remain intact.

## Debt-age business assumptions and algorithm
Source: frozen Statement V2 movements and finalized date (Vietnam local day), not legacy weekly headers, mutable close balances or transfer creation date.
1. Signed combined remaining obligations = Debt outstanding minus signed net Balance. Only the resulting positive exposure is aged. A positive wallet offsets exposure; Reserve and Refund liability are separate.
2. For each frozen period, use incremental economic obligations: debt delta minus Balance delta. Transfers have equal deltas and cancel; Debt Payment allocations also cancel. Payment/Offset/Service Settlement, Payment Adjustment and Payment Reversal are settlement effects, never new period capacity. Non-payment credits reduce capacity; posted interest increases capacity. No per-Payment Statement mapping is inferred.
3. Cover remaining exposure newest-to-oldest, including open-period economic capacity first (without inventing a finalized anchor), then frozen finalized buckets. The oldest bucket still covered supplies the finalized day; due date adds the current credit term. A transfer does not change either input or anchor. Partial Payment can advance the anchor.
4. Open-only exposure is UNFINALIZED. Uncovered positive legacy opening/coverage overflow, negative adjustment buckets, unclassified nonzero events, or edits to sources already captured in frozen Statements are REVIEW. REVIEW clears the displayed anchor and blocks future purchasing. No silent legacy migration or new accounting rule.
5. Statement attribution stays journal posting/reporting date. Late manual price is posted now, never inserted into an immutable historic Statement. Finalized bytes, signed Refund, interest→principal→wallet Payment settlement and one Debt/client are preserved.

Operational GET callers audited: financial detail/overview, client-orders financial projection, safePricing, control tower, BOD report and Statement preview explicitly request read-only account projection. Allocation/accrual remain on explicit posting/financial-command paths for compatibility; finalize explicitly prepares settlement/accrual before snapshot. Startup schema initialization is not a financial GET behavior.
Debt snapshots show posted unpaid interest plus a pure projection for completed, unposted days, using the same daily rounding and effective principal/rate segments as explicit accrual (current day excluded). The projection is labelled and is included as open-period coverage for age; it does not alter Ledger or immutable Statement totals. Payment/debt/finalize commands accrue completed days before settlement. A separate scheduler is not introduced.
