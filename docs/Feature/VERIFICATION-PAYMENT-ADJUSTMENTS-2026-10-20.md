## Implemented in this continuation

- FINANCE actual-receipt adjustment API/UI with immutable original Payment, signed linked adjustment ledger rows, before-allocation snapshots, reason/actor/audit and atomic Client/Sales notifications.
- Decrease consumes the original Payment's Balance portion before restoring paid Debt principal and interest. Increase pays current interest, principal, then Balance surplus. Full receipt delta plus the existing Debt exclusion conserve net Balance; no fake new Debt, Order cancellation or fee.
- Optimistic adjustment version; actor/key exact replay and payload conflict; freeze original surplus against later FIFO; prohibit generic ledger posting, Admin full reject or manual allocation bypass after an adjustment.
- All writes serialize in one immediate SQLite transaction. Failed notifications/audit/snapshot roll back money, allocations and receipts.
- Original/current amounts and read-only scoped history for ADMIN/BOD/SALES/CLIENT. Separate durable adjustment notices with recipient-only acknowledgement. Recent financial activity identifies adjustments rather than usage charges; new adjustment posting dates use the Vietnam calendar day.
- Reconciliation captures actual separately from original cents, including zero, without rewriting historical reconciliation rows. The additive nullable column preserves legacy evidence. Changed actual can be reconciled again with the same status; UI warns when latest reconciled amount differs.

## Exact support boundary

This is a legacy-ledger adapter. It **does not activate fc_* accounts or replace global allocateFIFO**. Before adjusting, legacy allocation/accrual is materialized in the same rollback-protected transaction. Any original allocation into a Statement is rejected with a migration message. Increased allocation with multiple unpaid legacy Debts is also rejected. No automatic historical mapping or deletion occurs. Consequently Payment Adjustment is not yet available for every existing Payment, and this is not full acceptance of the Owner financial rule set.

Payment Adjustment is excluded from legacy service-fee items and credit-note allocation. It must appear as financial activity in the pending full Statement snapshot implementation; the existing Statement screen is still legacy.
