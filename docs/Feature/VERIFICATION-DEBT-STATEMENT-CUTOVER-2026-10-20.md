# Verification — Statement-independent Debt and Payment cutover (20/10/2026)

**Status:** IMPLEMENTED + domain/API verified for the explicitly listed slice, NOT full Finance GĐ1 release or Owner UAT. Baseline origin/main `80a9fa8`.

## Owner-approved semantics implemented in the active application
1. Automatic settlement in `src/lib/credit.ts` now applies PAYMENT/OFFSET/SERVICE_SETTLEMENT to **Debt only**; remaining credit stays in Balance. There is no new Statement allocation; explicit Admin attempt to allocate to Statement is denied. Statement late due status is not a purchase block. Existing Debt overdue and independent Hold remain blocks. `purchasing_balance_cents` displays the positive portion of signed net Balance. Consolidated `receivable_cents` represents negative net Balance plus unpaid Debt, without adding previously charged Statement items again.
2. Manual Admin `action=debt` accepts total negative net Balance amount, deadline, optional prospective rate and reason, **without Statement/Order**. No fake fee, credit, Payment or actual Ledger posting. A Client's single `credit_debts` account is reused for top-ups and after full payoff; over-conversion is rejected. A transfer checks the exact net Balance movement in the same transaction, writes immutable `credit_balance_debt_transfers` and an audit record. The money-command receipt ensures idempotent retries.
3. Prior Payment surplus, already counted in Balance before Admin transfers a balance to Debt, is frozen from *retroactive* allocation using `credit_settlement_wallet_freezes`. Subsequent new Payments settle Debt (interest, principal) and the remaining amount stays in Balance. Raw `balance_cents` keeps historical entries; only the Debt reclassification affects `net_balance_cents` room.
4. New synthetic DB schema allows `credit_debts.source_statement_id = NULL`. Former Statement-source Debt accounts can accept independent Balance top-ups, tracked separately in `balance_topup_cents`; Statement original charge totals are not retroactively lowered. `receivables` now permits null Statement source.
5. Admin UI: `FinancialWorkspace` Controls has a Balance → Debt form when signed net Balance is negative; form is removed from Statement detail. Statement no longer presents a Payment-allocation target in the controls. Existing interest extension/modify workflow and read-only credit history remain.

- No operational DB reset, seed or mutation. Automated runs created their own temporary/test SQLite databases. Demo seed cleanup updated for new FK event/freeze tables. Untracked `Codex/` untouched.
- **Legacy schema guard:** any old DB still declaring `credit_debts.source_statement_id NOT NULL` cannot create a new Balance-origin Debt with no prior Debt row.
