## Implemented in the application

- `statement-journal.ts` installs append-only **reporting** triggers on the authoritative Ledger, Debt, allocation, daily-interest and Refund tables, in one immediate schema transaction. Source writes and reporting events share the source transaction and roll back together. No `fc_*` enrollment, second writable wallet, dual charge or invented Payment is introduced.
- Existing operational exposure is captured as an explicit signed opening checkpoint, including prior Bank refund totals. New empty DBs start with zero exposure. Reinitialization does not duplicate checkpoints. Periods before the checkpoint are unavailable; legacy Claim decisions and multiple Debt accounts block new snapshots until reconciliation. This is **not** a historical migration or a claim that old obligations have been proven correct.
- `statements-v2.ts` / `/api/statements-v2` provide scoped preview/list and ADMIN/FINANCE Finalize. Periods are consecutive and non-overlapping; future Finalize is denied. A unique Client/start and immediate transaction make concurrent retry return identical issued financial bytes. Changed period end conflicts. DB triggers reject update/delete of snapshots/events/checkpoint.
- Snapshot contains copied fees/adjustments, all recorded financial movements, Payment ID/Debt ID/interest cents, signed Balance/Debt/Refund openings and closings, recorded Bank outflow, captured Order membership, Credit Limit/Reserve references. Finalize performs no charge or Payment execution. Current references are captured **at finalization**, not reconstructed historical credit/reserve balances.
- Reporting uses actual posting order/time. Economic `occurred_at` stays visible. Anything recorded after a period Finalizes is carried to the next reporting period, including same-day entries, backdated fees/Payments, Payment corrections and source correction deltas. Issued source values/allocations remain copied and immutable.
- V2 Claim creation uses separate `source_statement_v2_id`, validates the snapshot's captured Order set and existing ownership rules. Open linked Order Claims derive Disputed; resolution changes that projection without modifying financial bytes. Finance/BOD read statements but do not gain Claim/Admin powers. Bank account/proof fields are omitted from Statement details.
- `addLedgerEntry` now runs Debt-first allocation before returning its receipt. Ledger ID determines chronological allocation, never backdated economic date. Every wallet surplus freezes at its first allocation. This fixes a reproduced bug where reducing another Payment restored Debt and a later read consumed a previously retained wallet surplus. Admin manual `allocate`/`apply_credit` is retired before mutations/receipts; partial receipt corrections stay in Finance Payment Adjustment. Original legacy allocation records remain for audit/migration.
- Operational Statement UI is replaced with V2; legacy backend charge materialization remains for existing adapters. The operational API removes Statement paid/outstanding/status fields, and overdue overview counts Debt only. Debt payment statuses remain appropriate for Debt accounts.
- BOD runs one transaction, provides period opening/closing plus exact issued snapshot, and separately labels current exposure, raw Ledger flows, Refund Bank execution dates and Statement posting periods. Projection totals cross-check Wallet/Debt/Refund and cumulative recorded Bank payouts. Unsupported/mismatched periods return an explicit unavailable reason, never fabricated reconciled zero.
